Documentación del Proyecto

Arquitectura, roles, decisiones técnicas y referencias del equipo.

Arquitectura de Red

La red implementada sigue un modelo Cliente-Servidor jerárquico y segmentado, reemplazando la propuesta inicial de red plana (Peer-to-Peer) con switch no administrable.

Principio rector: ningún equipo accede a la consola de AWS a través del internet público. Todo tráfico cloud pasa por el túnel VPN IPSec Site-to-Site gestionado por el Edge Gateway.

Componentes principales

  • Edge Gateway (Firewall Perimetral UTM): controla acceso a internet y establece el túnel VPN hacia AWS.
  • Switch Administrable Capa 3: segmenta la red en VLANs aisladas.
  • VLAN 10 — Administrativos: acceso filtrado a internet y herramientas ofimáticas.
  • VLAN 20 — Ingenieros: tráfico priorizado y altamente restrictivo, acceso a VPN AWS.
  • VLAN 30 — Servidores: controlador de dominio, DNS y DHCP internos.
  • Servidor Local (DC): Windows Server 2022 o Ubuntu Server con Samba/FreeIPA.

Por qué se descartó la red plana

Riesgo crítico: en una red plana sin segmentación, el compromiso de un equipo administrativo daría visibilidad directa sobre los ingenieros y las credenciales de AWS. El movimiento lateral sería irrestricto.

La propuesta inicial (switch básico + salida a internet directa) es técnicamente inviable para una empresa cuyo producto principal es la confidencialidad de datos de clientes.

Seguridad y Hardening

El enfoque de seguridad cubre tres capas: identidades, endpoints y red.

Gestión de identidades

  • Active Directory / LDAP como directorio centralizado único.
  • Autenticación Multifactor (MFA) obligatoria para todos los usuarios.
  • Políticas de contraseña robustas aplicadas vía GPO.
  • Separación estricta: administradores de dominio no tienen claves de AWS.

Hardening de endpoints

  • Cifrado de disco completo: BitLocker (Windows) y LUKS (Linux) en todos los equipos.
  • Bloqueo de puertos USB (prevención de fuga de datos — DLP).
  • GPOs que restringen permisos por perfil de usuario.
  • Prohibición de instalación de software no autorizado en puestos administrativos.

Seguridad de red

  • Firewall UTM perimetral con inspección de paquetes.
  • Segmentación VLAN impide movimiento lateral entre departamentos.
  • VPN IPSec cifrada para todo acceso a AWS.
  • Auditoría centralizada: logs de acceso para cumplimiento y trazabilidad.

Estas medidas garantizan los principios de confidencialidad, integridad y no repudio exigidos por el mercado colombiano para empresas de custodia de datos.

Integración Cloud — AWS

El acceso a AWS está restringido exclusivamente a través de la red privada de la empresa. No existe acceso directo desde internet.

Arquitectura de conexión

  • VPN Site-to-Site IPSec: túnel cifrado entre el Edge Gateway local y la VPC de AWS.
  • AWS IAM: principio de menor privilegio. Cada ingeniero tiene permisos mínimos necesarios para su función.
  • AWS CloudTrail: auditoría de todas las acciones realizadas en la cuenta.
  • S3 con cifrado en reposo: almacenamiento de datos con políticas de bucket restrictivas.

Principios aplicados

  • Separación de roles: quien administra la red local no tiene acceso a AWS y viceversa.
  • Acceso denegado por defecto; se otorgan permisos explícitamente.
  • Revisión periódica de políticas IAM para eliminar permisos no utilizados.

Referencia: Cisco Systems (2020) — Enterprise Campus Architecture Design Guide. La conexión híbrida local-cloud sigue el modelo de acceso seguro zero-trust adaptado al contexto de la empresa.
